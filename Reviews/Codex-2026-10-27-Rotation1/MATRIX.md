# Falsifiable review matrix

**Every candidate row is CANDIDATE_NOT_RUN.** E = executed harness calibration only;
W = awaits authorized immutable implementation + adapter; O = later operational authorization.
Static and future adapter procedures do not imply permission to run the game. Severity:
H safety/authorization/integrity, M availability/reproducibility, L reporting/hygiene.

Each negative case requires a matching reason, a positive control and direct independent
side-effect checks. Generic `throws`, `Incomplete`, `success=false` or exit1 is insufficient.
Blocked/unsupported cases are not silently omitted or counted as passes.

## Required methodology controls

| ID | Control / independent oracle | Expected / readiness |
|---|---|---|
| M01 | Per-worktree lock negative calibration: same declared resource, distinct explicit file paths; parent observes both owners | Must detect violation (N01 executed); not evidence about candidate mapper |
| M02 | False-success negative: synthetic protected bytes changed while reported success could remain true | Must detect SHA difference (N02 executed); endpoint hashes still cannot detect all round trips |
| M03 | Unsafe check/use writer swaps parent at deterministic boundary, independent protected canary changes | Must detect (N03 executed), not claim a production exploit or race fix |
| M04 | Positive real effect after acquisition checked against independently observed Popen PID and bytes | L14 executed; prevents refuse-everything/no-op test doubles appearing safe |
| M05 | Candidate guard-returning-false/throwing stub but helper still writes or fake-launch counter increments | Must fail later integrated test, W; no reliance on same validation helper as oracle |
| M06 | Failing compile/import/worker protocol or wrong expected error | Harness error, never a killed mutant/Pass; fail-fast but preserve partial evidence |
| M07 | Fresh fixture root per repeat; reverse scheduling; source/adapter/host pins | Repeated self-test now; candidate reproducibility W; no claim all interleavings covered |

Rows W/O remain visible even if an implementation omits their feature. A predeclared, safely
rejected unsupported operation can satisfy its refusal contract; lack of a test seam or required
evidence is Blocked, not equivalent to safe rejection. No matrix completion upgrades runtime
authorization, isolation, equipment correctness, neutral certification or rollback safety.
